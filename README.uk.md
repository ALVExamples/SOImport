# Імпорт заявок з xlsx

[English](README.md) · **Українська**

Вебсторінка, яка імпортує заявки з xlsx-файлу в MySQL.

Наданий файл містить 100 000 рядків і важить 11 МБ. Умова — усі рядки мають записатися в базу при стандартному `max_execution_time=30`. У цьому проєкті стандартною залишена вся конфігурація PHP, а не лише ця директива:

| Параметр              | Значення |
|-----------------------|----------|
| `max_execution_time`  | 30       |
| `upload_max_filesize` | 2M       |
| `post_max_size`       | 8M       |
| `memory_limit`        | 128M     |

В nginx також залишено типовий `client_max_body_size` — 1 МБ.

На наданому файлі імпорт триває близько 23 секунд і записує рівно 100 000 рядків.

## Стек

- Laravel 13, PHP 8.4 (php-fpm)
- Vue 3, Vite 8, Tailwind CSS 4
- MySQL 8.4
- nginx
- черга Laravel на драйвері `database`
- Docker Compose

Сторонніх PHP-бібліотек для читання xlsx немає — лише вбудовані розширення `zip` та `xmlreader`.

## Запуск

Потрібен лише Docker з Docker Compose.

```bash
docker compose up -d --build
```

Після старту сторінка імпорту доступна на <http://localhost:8080>.

Інший порт: `APP_PORT=8090 docker compose up -d --build`. Решта параметрів (назва бази, паролі, розмір пачки) перелічені в `.env.example`; щоб їх змінити, скопіюйте його в `.env`. Файл `.env` необов'язковий — усі параметри мають типові значення.

| Сервіс  | Призначення |
|---------|-------------|
| `web`   | nginx: віддає статику та проксіює PHP-запити в php-fpm |
| `app`   | php-fpm; під час старту генерує `APP_KEY` і виконує міграції |
| `queue` | воркер черги (`queue:work --timeout=30`), який виконує імпорт |
| `db`    | MySQL 8.4 з власним томом; порт назовні не публікується |

Усі сервіси працюють в окремій мережі `soimport-network`. Дані бази та завантажені файли зберігаються в томах `db-data` і `app-storage`.

Зупинити: `docker compose down`. Зупинити й видалити дані: `docker compose down -v`.

## Тести

```bash
docker compose run --rm tests
```

Тести запускаються в окремому контейнері без мережі на SQLite in-memory. Не запускайте `php artisan test` усередині контейнера `app`: його змінні оточення вказують на робочу базу MySQL і перекривають `phpunit.xml`.

## Як це працює

### 1. Завантаження частинами

Браузер ріже файл на частини по 512 КБ і надсилає їх по одній на `POST /imports/chunks`. Саме це дозволяє файлу в 11 МБ пройти стандартні ліміти завантаження. Після останньої частини `POST /imports` склеює їх, перевіряє, що вийшов справжній xlsx (zip-архів, у якому є `xl/workbook.xml`), створює запис в `imports` і ставить задачу в чергу. Запит повертає відповідь одразу.

### 2. Потокове читання

Файл xlsx — це zip-архів з XML-файлами всередині. `XlsxSheetReaderService` читає XML аркуша просто з архіву через `XMLReader` поверх обгортки `zip://`, по одному рядку. Файл не розпаковується на диск і не завантажується в пам'ять, тому пікове споживання пам'яті — близько 30 МБ, хоча розпакований аркуш важить 61 МБ. Більша частина цієї пам'яті — таблиця спільних рядків, яку доводиться тримати цілком.

Колонка комірки визначається за її адресою (`K7`), а не за порядком, бо порожні комірки в XML просто відсутні.

### 3. Імпорт кроками з бюджетом часу

`ImportLeadsJob` працює з бюджетом у 20 секунд. Після кожної вставленої пачки він перевіряє час; коли бюджет вичерпано, зупиняється і ставить у чергу таку саму задачу, яка продовжує зі збереженого курсора. Задача також має жорсткий тайм-аут у 30 секунд за реальним часом.

Воркер черги — це CLI-процес, де `max_execution_time` типово не обмежений. Просто винести роботу в чергу й дати їй працювати хвилину означало б виконати умову лише на папері, тому обмеження накладено явно.

### 4. Без втрат і дублів

Рядки вставляються пачками по 1000. Вставка і зсув курсора (`imports.cursor_row`) виконуються в одній транзакції, тож курсор завжди відповідає тому, що реально є в базі. Якщо воркер впаде посеред кроку, наступний крок продовжить з останньої зафіксованої пачки.

Унікальний ключ `(import_id, source_row)` — друга лінія захисту: база сама не дасть записати той самий рядок файлу двічі.

### 5. Прогрес

Сторінка раз на секунду опитує `GET /imports`, поки є незавершені імпорти, і показує статус, смугу прогресу, кількість записаних рядків, кількість рядків із зауваженнями та час обробки. Імпорт не залежить від браузера — вкладку можна закрити.

### Час на наданому файлі

| Операція | Час |
|----------|-----|
| Підрахунок рядків (для смуги прогресу) | 0,2 с |
| Завантаження таблиці спільних рядків | 0,25 с |
| Читання та перетворення всіх рядків, без бази | 5,4 с |
| Повний імпорт | близько 23 с (два кроки: 20 с + 3 с) |

Основний час іде на вставку в MySQL, а не на розбір файлу.

## Обробка даних

За умовою мають записатися всі рядки, тому жоден рядок не відкидається.

- **Дублікати зберігаються.** 205 значень `external_id` у файлі повторюються. Усі такі рядки записуються, тому в `leads` рівно 100 000 рядків, з них 99 795 з унікальним `external_id`.
- **Некоректні значення зберігаються з позначкою.** Значення записується як є, а в JSON-колонку `leads.issues` потрапляє, що саме не так, наприклад `{"phone": "invalid"}`. У наданому файлі таких рядків 1627: 813 з некоректним телефоном, 822 з некоректним email, 8 — з обома.
- **Телефони** нормалізуються до формату `+380XXXXXXXXX`. Для комірок, де формула дала помилку (`#ERROR!`), береться вихідний текст формули — саме його ввела людина.
- **Дати** в Excel зберігаються як серійні числа; вони перетворюються на `DATETIME` без зсуву часового поясу.
- **Порожні комірки** стають `NULL`.
- **Колонки шукаються за назвою** в заголовку, а не за позицією. Якщо бракує будь-якої з 15 очікуваних колонок, імпорт завершується помилкою з їх переліком.

## Структура БД

Міграції лежать у `database/migrations`, повний SQL-дамп структури — у `dump.sql` в корені проєкту (копія — у `database/structure.sql`).

- `imports` — завантажені файли: статус, кількість рядків, курсор, кількість рядків із зауваженнями, текст помилки.
- `leads` — заявки: 15 колонок файлу, а також `import_id`, `source_row` (номер рядка в аркуші) та `issues`.

На `external_id` є індекс, але він не унікальний. Довідникові значення (місто, джерело, продукт, менеджер) зберігаються звичайними рядками.

```
app/
├── Enums/                  ImportStatus, LeadStatus
├── Http/
│   ├── Controllers/        ImportController
│   ├── Requests/           StoreChunkRequest, StoreImportRequest
│   └── Resources/          ImportResource
├── Jobs/                   ImportLeadsJob
├── Models/                 Import, Lead
└── Services/
    ├── Import/             ChunkedUploadService, LeadImporterService, LeadRowMapperService
    └── Xlsx/               XlsxSheetReaderService
config/import.php           бюджет часу, розмір пачки, ліміти розміру
database/migrations/        imports, leads
database/structure.sql      SQL-дамп структури
docker/                     entrypoint.sh, nginx.conf
resources/js/               api.js, components/ImportPage.vue
resources/views/            imports.blade.php
tests/                      Unit, Feature, Support/XlsxFixture
dump.sql                    SQL-дамп структури
compose.yaml, Dockerfile
```

| Клас | Відповідальність |
|------|------------------|
| `ImportController` | Тонкий HTTP-шар: сторінка, приймання частин, створення імпорту, прогрес. |
| `ChunkedUploadService` | Зберігає частини, збирає файл, перевіряє його розмір і формат. |
| `ImportLeadsJob` | Один крок імпорту в черзі; ставить себе знову, доки файл не закінчиться. |
| `LeadImporterService` | Виконує один крок: читання з курсора, пачка, вставка, зсув курсора. |
| `XlsxSheetReaderService` | Потоковий читач аркуша xlsx. Нічого не знає про заявки. |
| `LeadRowMapperService` | Перетворює комірки аркуша на рядок `leads` і перелік зауважень. Нічого не знає про xlsx і базу. |

## HTTP API

| Метод | Шлях              | Призначення |
|-------|-------------------|-------------|
| GET   | `/`               | Сторінка імпорту. |
| POST  | `/imports/chunks` | Приймає одну частину: `upload_id`, `index`, `chunk`. Відповідь 204. |
| POST  | `/imports`        | Завершує завантаження: `upload_id`, `name`, `chunks`. Відповідь 201 з імпортом. |
| GET   | `/imports`        | 10 останніх імпортів із прогресом. |
| GET   | `/imports/{id}`   | Один імпорт. |

## Відомі обмеження

- **Розмір файлу.** Кожен крок, крім першого, мусить промотати аркуш до курсора. Це коштує 2,2 с на 90 000 рядків і зростає лінійно. На файлах у кілька сотень тисяч рядків сама промотка перестане вміщатися в крок; точну межу не вимірювали. Для більших файлів потрібен інший спосіб відновлення, наприклад проміжний файл з переходом за байтовим зсувом.
- **Читається лише перший аркуш** книги.
- **Немає повторних спроб завантаження.** Невдалий запит із частиною перериває завантаження, а обмеження кількості запитів перед застосунком його зламає.
- **Покинуті завантаження** залишають свої частини на диску; автоматично вони не видаляються.
- **Повторний імпорт того самого файлу** створить ще 100 000 рядків.
- **Немає автентифікації** та сторінки перегляду самих заявок.
